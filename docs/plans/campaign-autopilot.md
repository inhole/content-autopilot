# 체험단 자동화 계획과 현황 (카카오톡 선물하기)

카카오톡 선물하기 체험단의 공개 목록을 모아 고르고, 신청·결과·리뷰 기한을 챙기고, 리뷰 초안을 쓰는 파이프라인이다. 동작은 [architecture.md](../architecture.md#체험단-파이프라인), 운영은 [operations.md](../operations.md#체험단), 결정과 이유는 [decisions.md](../decisions.md) 9~12를 본다. 구현하면서 바뀌는 결정은 이 문서와 `decisions.md`에 같이 적는다.

## 1. 방향이 바뀐 이유

처음 계획은 **레뷰(revu.net) 공고를 카카오톡 PC 단체방에서 읽고, Aside 브라우저로 신청하고, 네이버 블로그에 임시저장**하는 구조였다. 인터뷰 때 세운 가정이었는데 틀렸다.

- 실제로 하려는 체험단은 **카카오톡 선물하기 체험단**이다. 레뷰도 네이버 블로그도 쓰지 않는다.
- 선물하기 체험단 목록은 gift.kakao.com의 공개 JSON이다. 카톡을 읽을 필요가 없다.
- 신청과 리뷰 작성은 카카오톡 **모바일 앱 전용**이다. 데스크톱으로 열면 모바일 전용 안내 페이지로 간다. 신청 폼에는 옵션 선택과 배송지뿐이다.

그래서 카톡 읽기, 로컬 PC 워커, Aside, 레뷰 신청, 네이버 임시저장, `WORKER_ROLE`, dry-run을 모두 없앴다. 신청과 리뷰는 내가 폰에서 하고 Telegram 버튼으로 기록한다.

## 2. 구현한 것 (`feat/campaign-autopilot`)

마이그레이션 `014`(`campaigns`, `campaign_reminders`)와 `src/campaigns/`. 워커 하나가 모두 처리한다.

| 단계 | 내용 |
|---|---|
| 수집 | `gift-collect`가 하루 3번(09·15·21시, `GIFT_COLLECT_CRON`) 공개 목록 전체를 읽어 `campaigns`에 upsert한다. 상태와 내 기록은 건드리지 않는다. |
| 선별 | 규칙(제외 키워드·브랜드, `maxCompetition`, 마감)으로 거르고, 남은 후보를 LLM이 60건씩 점수화해 하루 `CAMPAIGN_DAILY_MAX`개를 뽑는다. |
| 카드 | 사진 카드에 경쟁률, `D-n (추정)`, 점수와 이유를 담고 `📱 선물하기에서 열기` / `✅ 신청함` / `🙅 패스`(사유 선택) 버튼을 붙인다. |
| 기록 | `✅` 뒤 `🎉 선정` / `😢 미선정`. `/due <번호> <날짜>`로 리뷰 기한. `/camps`로 진행 중 목록. |
| 유지보수 | `campaign-maintenance`가 매시 마감 지난 카드를 `EXPIRED`로 만들고, 09~21시에 리마인더(`result-check`, `due-missing`, `review-d3/d1/d0`)를 보낸다. |
| 리뷰 초안 | `📝 리뷰 초안 쓰기` → 안내 메시지에 메모 답장 → `review-draft` → 초안 메시지(복사용) + 조작 메시지(`🔁 다시 쓰기` / `✅ 리뷰 올림`). `수정:` 답장은 그대로 교체, 그 외 답장은 피드백. 광고 표기는 코드가 앞에 붙인다. |
| 대시보드 | 읽기 전용 웹 페이지([dashboard.md](../dashboard.md))와 `/status`에 체험단 단계별 개수. |
| CLI | `gift:list`(읽기 전용), `campaign:collect`, `campaign:rank`, `campaign:show`, `campaign:card`, `campaign:remind`, `review:draft` |

설정은 `GIFT_COLLECT_CRON`, `GIFT_TRIAL_PAGE_ID`(33325), `CAMPAIGN_DAILY_MAX`(5), `CAMPAIGN_PROFILE_PATH`(`config/campaign-profile.json`)다.

## 3. 실제로 확인한 것 (2026-10-18)

- 공개 목록 API가 로그인 없이 응답한다. 첫 페이지 50건, 이후 24건씩 `collections?page=2…`로 이어지고, 마지막 페이지(19번째, 17건)에서 `paging.isLast = true`다. 합계 **475건**, 20페이지부터는 빈 `items`다.
- 페이지네이션이 끝까지 돈다. 같은 `campaignId`는 한 번만 담긴다.
- upsert가 멱등이다. 두 번 돌려도 새 행이 생기지 않고, 상태·점수·`updated_at`이 바뀌지 않는다.
- 형식 검증이 엄격하다. 필수 필드가 빠지거나 구조가 다르면 조용히 넘어가지 않고 실패한다.

## 4. 아직 확인하지 못한 것

| 항목 | 왜 중요한가 | 확인 방법 |
|---|---|---|
| `remainingDays`의 의미 | 신청 마감 추정(오늘 + 남은 일수의 끝)과 `EXPIRED`, `result-check` 시점이 모두 여기에 달려 있다. 당일 마감이 0인지 1인지, 실제 마감 시각이 언제인지 모른다. | 마감일이 알려진 체험단을 며칠 추적해 `remaining_days` 변화와 카톡의 실제 마감을 비교한다 |
| LLM 선별 품질 | 475건 중 하루 5개를 뽑는 것이 핵심이다. 점수가 취향과 맞는지, 60건 배치 간 점수 편차가 없는지 모른다. | 첫 1~2주의 카드와 `🙅 패스` 사유를 모아 프롬프트와 프로필을 조정한다 |
| 실제 봇의 사진 카드 | 이미지 URL이 Telegram에서 받아지는지, 캡션이 1024자 안에서 보기 좋은지 확인하지 못했다. | `campaign:collect` 또는 `campaign:card <id>`로 실제 봇에 보낸다 |
| 폰에서 링크가 카톡으로 열리는지 | `gift.kakao.com/giftbox/trial-campaign/<id>`를 Telegram에서 폰으로 열었을 때 카카오톡 앱의 해당 체험단으로 가는지, 브라우저로 열리는지 모른다. 브라우저로 열리면 신청 동선이 늘어난다. | 폰 Telegram에서 카드 버튼을 눌러 본다 |
| 리뷰 초안 품질 | 메모만 근거로 한 100~500자 초안이 쓸 만한지, 글자 수 보정(줄이기·늘리기)이 자연스러운지 모른다. | 선정된 건으로 한 번 끝까지 돌려 본다 |
| 리마인더 시점 | `result-check`가 "신청 마감 하루 뒤"인 것이 실제 발표 시점과 맞는지 모른다. | 첫 신청 건의 실제 발표일과 비교한다 |

## 5. 다음 단계

1. 위 미확인 항목을 첫 1~2주 운영하면서 확인한다. 가장 먼저 사진 카드와 폰에서 링크 열림을 본다.
2. `remainingDays` 실측 결과로 마감 추정을 고친다. 맞으면 `(추정)` 표시를 줄이는 것도 본다.
3. 선별 결과가 나오면 프롬프트와 `config/campaign-profile.json`(`interests`, `excludeKeywords`, `maxCompetition`)을 조정한다.
4. **무신사 프리유저**를 별도 단계로 검토한다. 이 쪽은 PC에서 신청할 수 있고 로그인이 필요해서, 브라우저 자동화(Aside)를 다시 쓸 수 있다. 이 단계는 지금 구현에 없다. 쓰기로 하면 새 출처(`campaigns.source`), 로그인 세션 관리, 신청 방식을 따로 설계한다. 선물하기 쪽 구조는 건드리지 않는다.

## 6. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 선물하기 목록 API 형식이 바뀌거나 막힌다 | 스키마를 엄격히 검사해 실패를 알린다(수집 job 최종 실패 시 Telegram ❌). 첫 페이지 실패는 에러, 이후 페이지 실패는 읽은 만큼 사용. 요청 간격 0.4초, 하루 3회. |
| 공개 API라도 약관·접근 제한이 있을 수 있다 | 읽기 전용, 낮은 빈도, 로그인·신청 자동화 없음. 문제가 보이면 `GIFT_COLLECT_CRON` 횟수를 줄이거나 끈다. |
| 마감 추정이 틀려 신청 가능한 카드가 일찍 만료된다 | 마감은 `(추정)`으로 표시하고, 실제 마감은 카톡에서 확인한다. 만료된 카드는 버튼이 지워지고 다시 살릴 수 없으므로(`campaign:card`로 다시 보내도 등록되지 않는다), 추정이 틀린 것으로 보이면 계산을 먼저 고친다. |
| 리뷰 초안이 써보지 않은 경험을 지어낸다 | 메모만 근거로 쓰게 하고, 사람이 읽고 직접 올린다. 코드는 게시하지 않는다. |
| 광고 표기가 빠진다 | 코드가 모든 초안 맨 앞에 붙인다(결정 12). |
| 기록 버튼을 빼먹어 리마인더가 어긋난다 | 결과 확인·기한 누락 리마인더가 되묻는다. `/camps`로 상태를 훑는다. |
